### Task 1: Check `-s` before the full-screen timer opens its screen (bead `clitimer-6f5.2`)

**Files:**
- Modify: `src/main.rs` (`run_timer`, around lines 47-53)
- Test: `tests/cli.rs`

**Interfaces:**
- Consumes: `cli_timer::sound::check(&Sound) -> Result<(), SoundError>`; `App::sound: Sound` (public field).
- Produces: nothing new.

- [ ] **Step 1: Write the failing tests** in `tests/cli.rs`, next to the other bad-sound-file tests.

The existing `run` helper has no deadline, and the unfixed binary opens the alternate screen and
waits for a key until killed (measured by the plan red team). So add a helper
`fn run_within(args: &[&str], deadline: Duration) -> Output`: spawn as `run` does (same env,
`stdin` null, `stdout`/`stderr` piped), poll `try_wait` until `deadline`, and on expiry kill the
child and `panic!("cli-timer {args:?} still running after {deadline:?}")`. Drain stdout/stderr on
threads so a full pipe can't block the child. Also add
`const ALTERNATE_SCREEN: &str = "\x1b[?1049h";`.

```rust
#[test]
fn the_full_screen_timer_rejects_a_missing_sound_file_before_starting() {
    let output = run_within(&["-t", "1s", "-s", "nope.wav"], Duration::from_secs(5));
    let stderr = text(&output.stderr);
    assert_eq!(output.status.code(), Some(1), "{stderr}");
    assert!(stderr.contains("cannot open sound file nope.wav"), "{stderr}");
    assert!(!stderr.contains(ALTERNATE_SCREEN), "the screen opened: {stderr:?}");
}

#[test]
fn the_full_screen_timer_rejects_a_file_that_is_not_audio() {
    let not_audio = concat!(env!("CARGO_MANIFEST_DIR"), "/Cargo.toml");
    let output = run_within(&["-t", "1s", "-s", not_audio], Duration::from_secs(5));
    let stderr = text(&output.stderr);
    assert_eq!(output.status.code(), Some(1), "{stderr}");
    assert!(stderr.contains("cannot decode sound file"), "{stderr}");
    assert!(!stderr.contains(ALTERNATE_SCREEN), "the screen opened: {stderr:?}");
}
```

- [ ] **Step 2: Run them to see them fail**

Run: `cargo test --test cli the_full_screen_timer_rejects`
Expected: both FAIL by name, either with the `still running after 5s` panic (a console is attached, as on this machine) or on the `ALTERNATE_SCREEN` / exit-code assertion (no terminal). Neither may hang.

- [ ] **Step 3: Implement.** In `run_timer`, right after `App::new(...)` and before building the terminal, call `cli_timer::sound::check(&app.sound)?`. `SoundError` converts into the boxed error with `?`; `main` already prints `Error: {e}` and exits 1.

- [ ] **Step 4: Run the gates**

Run: `cargo fmt --all && cargo clippy --all-targets -- -D warnings && cargo test`
Expected: all pass, including both new tests.

### Task 2: Show the day in the human "set" line when it isn't today (bead `clitimer-6f5.3`)

**Files:**
- Modify: `src/output.rs` (`write_event`, the `Event::Set` arm; the tests module)

**Interfaces:**
- Produces (all private to `src/output.rs`):
  - `fn clock(at: &DateTime<Local>, today: NaiveDate) -> String`
  - `fn write_text(out: &mut impl Write, event: &Event, today: NaiveDate) -> io::Result<()>`: the current text branch of `write_event`, with the `Event::Set` arm using `clock(fires_at, today)`.
  - `write_event` keeps its signature; its text branch becomes `write_text(out, event, Local::now().date_naive())`. That call is the only place the clock is read, and no test goes through it with a `Set` event.

Format rules (chrono strftime):
- same date as `today`: `%H:%M:%S` → `14:32:05`
- other date, same year: `%a %-d %b %H:%M:%S` → `Sat 24 Oct 14:32:05`
- other year: `%a %-d %b %Y %H:%M:%S` → `Sat 1 Jan 2028 09:00:00`

- [ ] **Step 1: Write the failing tests** in the `tests` module of `src/output.rs` (the existing `at(h, m, s)` helper fixes the date at 2026-10-22, a Thursday; add two helpers, `on(y, mo, d, h, m, s) -> DateTime<Local>` and `date(y, mo, d) -> NaiveDate`; weekdays checked: 2026-10-22 Thu, 2026-10-23 Fri, 2028-01-01 Sat):

```rust
#[test]
fn clock_is_the_bare_time_today() {
    assert_eq!(clock(&at(14, 32, 5), date(2026, 10, 22)), "14:32:05");
}

#[test]
fn clock_shows_the_day_when_it_is_not_today() {
    assert_eq!(clock(&on(2026, 10, 23, 1, 0, 0), date(2026, 10, 22)), "Fri 23 Oct 01:00:00");
}

#[test]
fn clock_shows_the_year_when_it_is_another_year() {
    assert_eq!(clock(&on(2028, 1, 1, 9, 0, 0), date(2026, 10, 22)), "Sat 1 Jan 2028 09:00:00");
}
```

Change the existing `human_set_line` test to go through `write_text` with `today = date(2026, 10, 22)` (the `set` helper's date), keeping its expected strings `"Reminder set: \"check the oven\" at 14:32:05\n"` and `"Reminder set at 14:32:05\n"`. Add:

```rust
#[test]
fn human_set_line_on_another_day() {
    // write_text into a Vec, as event_text does, with today = date(2026, 10, 21)
    assert_eq!(text_on(&set(Some("x")), date(2026, 10, 21)), "Reminder set: \"x\" at Thu 22 Oct 14:32:05\n");
}
```

(`text_on(event, today) -> String` is a test helper beside `event_text`.) No test reads the real clock for a `Set` line, so none can change result with the date.

Run: `cargo test --lib output::`
Expected: compile error, `clock` / `write_text` not found.

- [ ] **Step 3: Implement `clock` and `write_text`** as in Interfaces.
