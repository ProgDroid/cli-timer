Gates run by the reviewer: `cargo fmt --all --check` exit 0; `cargo clippy --all-targets -- -D warnings`

not a hang.

### Strengths

- **The `-s` fix is minimal and in the right place** (`src/main.rs:49-50`): `sound::check(&app.sound)?`
  runs after `App::new` and before `CrosstermBackend`/`tui.init()`, so it never touches the terminal.
  It reuses the same `check` as `remind` and `ding`, and the comment says why it comes first.
- **Both failure classes are pinned** (Review Focus 3): a missing file (`SoundError::Open`) and a file
  that exists but is not audio (`Cargo.toml`, `SoundError::Decode`). `check` builds a `Decoder`, which
  probes the header, so a decode error does fail early.
- **`run_within` is careful**: pipes drained on threads, the child killed and reaped on expiry, and a
  named panic rather than a hung test. The red log shows it working.
- **Portability of the new e2e tests is sound.** On the fixed binary they exit before any terminal
  call, so they don't depend on a tty. On an unfixed binary they still fail on every OS: with a console
  (Windows locally) the deadline trips; on a Linux runner with no tty, crossterm's `enable_raw_mode`
  fails on `/dev/tty`, the binary exits 1 with a different message, and the
  `contains("cannot open sound file nope.wav")` assertion catches it. The test does not depend on the
  `ALTERNATE_SCREEN` assertion to fail.
- **`clock` matches the plan's interfaces exactly**, and the clock is read in one place only
  (`write_event`'s call to `write_text`). Tests pass `today` in and use exact strings. chrono's
  `%a`/`%b` are English whatever the locale (no `unstable-locales` feature), so the expected strings
  hold on every runner.
- **Review Focus 1 (crossing midnight)** is pinned by `clock_shows_the_day_when_it_is_not_today`
  (23 Oct 01:00 against today 22 Oct gives `Fri 23 Oct 01:00:00`) and end to end through `write_text`
  by `human_set_line_on_another_day`. **Focus 2 (another year)** is pinned by
  `clock_shows_the_year_when_it_is_another_year`. Since `remind` allows up to 100 days
  (`SKILL.md:44`), the year branch is reachable, so the ruling is justified.
- **Focus 5 (licence drift)**: `plugin_licence_matches_crate` pins both the literal SPDX id and equality
  with `CARGO_PKG_LICENSE`, so a change to either file fails it.
- **Focus 4 (no `-s`)**: `App::new` defaults to `Sound::Alarm`, and `built_in_sounds_pass_check`
  (`src/sound.rs:318`) covers `check(&Sound::Alarm)`. No new test is needed, as the plan says.
- Housekeeping matches the plan: each fix commit removes its own parking-lot entry and carries its bead
  id in the body, the `Cargo.lock` diff is just the version line, both manifests bumped together,
  JSON output and exit codes unchanged, `NEXT.md` not committed on the branch.

#### Minor (Nice to Have)

1. **`tests/cli.rs:522-536`: the plugin.json read is duplicated.** `plugin_licence_matches_crate`
   repeats `plugin_version_matches_crate`'s path, read and parse. A third manifest field would make
   three copies. Fix: extract `fn plugin_manifest() -> Value` and call it from both tests. Optional.
2. **`tests/cli.rs:61`: `ALTERNATE_SCREEN` rarely has teeth.** On Windows, crossterm may enter the
   alternate screen through WinAPI and write no escape bytes, and on a Linux runner with no tty the
   unfixed binary fails at raw mode before writing them. The assertion is harmless, and the other two
   assertions are the real guard (see Strengths), but a reader may think it is the main check. Fix, if
   wanted: a one-line comment saying it is a backstop. No code change needed.
3. **`src/output.rs:136`: redundant import.** `use chrono::{NaiveDate, ...}` in the tests module
   repeats what `use super::*` already brings in. It compiles clean and clippy is silent; drop it if
   you touch the file again.
4. **The `.beads/issues.jsonl` export for closing `clitimer-6f5.4` landed in the bump commit
   (1b54bd6)**, not in the licence commit, because `bd close` ran after that commit. This is
   bookkeeping only, and the squash merge removes it.
5. **Observation, no action: a reminder that crosses New Year** (`remind 2h` at 23:00 on 31 Dec)
   prints `Fri 1 Jan 2027 01:00:00`, with the year, even though it is two hours away. That follows the
   ruling and is unambiguous, so I consider it acceptable.

### Declined to judge

- TOCTOU on `-s`: a file that passes `check` and is then deleted or replaced before the timer fires
  still fails invisibly at fire time. Outside the spec, which asks only for a check before the screen
  opens. The fire-time error path (`App::tick`'s `eprintln!` into the alternate screen) is unchanged.
- A valid `-s` file starting the full-screen timer end to end: this needs a real terminal, so it can't
  be tested in CI. Covered at unit level by `a_valid_wav_file_passes_check_and_decodes`, and in
  v0.2.0's hands-on checklist.
- A 0s reminder within milliseconds of midnight: `fires_at` is computed before `write_event` reads
  `Local::now()`, so the line could show yesterday's date. Accepted in the plan (Task 2 Step 4), and
  the e2e `starts_with` checks still pass.
- Leftover console state if the *unfixed* binary is killed by `run_within` on a machine with a console
  (raw mode or the alternate screen left on). This only happens when the regression is present, and
  the panic names the cause.
- `plugin validate`'s ICON_MISSING warning: covered by the executor's ruling, and unrelated to this
  batch.
- Release steps (Task 4 Steps 2-7: merge, push, dry run, tag, install): not in the reviewed range.
